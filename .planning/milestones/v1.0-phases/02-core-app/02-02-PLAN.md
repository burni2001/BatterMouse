<feature>
  <name>HidReader — blocking read thread with ParseBattery</name>
  <files>BatterMouse/HidReader.cs, BatterMouse.Tests/HidReaderTests.cs</files>
  <behavior>
    - ParseBattery(report) returns report[5] as int when report.Length > 5
    - ParseBattery returns null when report is empty
    - ParseBattery returns null when report.Length == 5 (offset 5 does not exist)
    - ParseBattery returns 20 when report[5] == 20 (boundary case)
    - Start() launches a background Thread (IsBackground=true) running the read loop
    - Read loop: DeviceList.Local.GetHidDevices(VID, PID_WIRELESS) + PID_WIRED fallback;
      TryOpen() on each candidate; stream.ReadTimeout = Timeout.Infinite;
      calls ParseBattery on each read; raises BatteryLevelReceived if non-null
    - On IOException (device disconnected): log to Debug, sleep 5s, re-enumerate
    - On device not found: sleep 5s, retry
    - Stop() signals CancellationToken to terminate the loop
  </behavior>
  <implementation>
    Implement HidReader as a non-static class with BatteryLevelReceived event.
    ParseBattery is a public static method (tests call it directly, no instance needed).
    The background thread should be IsBackground = true so it does not prevent process exit.
    Use CancellationTokenSource for Stop().

    Critical pitfalls to avoid (from RESEARCH.md):
    - Do NOT set stream.ReadTimeout to anything other than Timeout.Infinite — wireless
      reports arrive infrequently (>20s); a timeout will cause spurious failures
    - Do NOT use the deprecated HidDeviceLoader API — use DeviceList.Local.GetHidDevices()
    - Do NOT filter by usage_page as a GetHidDevices parameter — it is not supported;
      enumerate all VID/PID matches and TryOpen() each
    - Ghost TLC (path 9&248e17d0 from Phase 1) will never produce data; TryOpen() returns
      true but Read() blocks forever on it — accept this: the CancellationToken will
      eventually unblock the loop on Stop()

    Enumerate PID_WIRELESS first, then PID_WIRED. Use the first candidate that TryOpen()
    succeeds on. Note in a code comment that PID_WIRED (0xD037) protocol is unverified.
  </implementation>
</feature>

  <behavior>

    - OnBatteryLevel(20) calls the callback with 20
    - OnBatteryLevel(15) calls the callback with 15
    - Two calls OnBatteryLevel(20) then OnBatteryLevel(18): callback fires exactly once
    - Three calls 20, 50, 20: callback fires exactly twice (resets on recovery above 20)
    - OnBatteryLevel(50) with no prior low call: callback never fires

    ToastHelper.ShowLowBattery(level):
    - Calls new ToastContentBuilder().AddText(...).AddText(...).Show()
    - Text includes the level value and "BatterMouse"
    - Must NOT call NotifyIcon.ShowBalloonTip (banned — Windows 11 Action Center broken)
  </behavior>
  <implementation>
    BatteryMonitor:
    - private bool _notified = false
    - private const int Threshold = 20
    - Constructor takes Action&lt;int&gt; callback, stores it
    - OnBatteryLevel: if level &lt;= Threshold &amp;&amp; !_notified → set _notified=true, call callback(level)
                     else if level > Threshold → set _notified=false (reset for next drop)

    AppContext (plan 02-03) will construct BatteryMonitor with ToastHelper.ShowLowBattery
    as the callback. Tests construct it with a lambda spy.

    ToastHelper:
    - Static class, static ShowLowBattery(int level)
    - Body: new ToastContentBuilder().AddText("BatterMouse — Low Battery").AddText($"Mouse battery is at {level}%. Connect USB cable to charge.").Show()
    - Call ToastNotificationManagerCompat.Uninstall() on app exit (AppContext.ExitThreadCore
      will call this — ToastHelper should expose a static Cleanup() method for this)
  </implementation>

<feature>
  <name>StartupManager — HKCU registry auto-start</name>
  <files>BatterMouse/StartupManager.cs, BatterMouse.Tests/StartupManagerTests.cs</files>
  <behavior>
    - SetStartup(true) writes value "BatterMouse" = "\"&lt;exePath&gt;\"" under HKCU Run key
    - SetStartup(false) deletes value "BatterMouse" from HKCU Run key (no-op if absent)
    - IsStartupEnabled() returns true if value "BatterMouse" exists under HKCU Run key
    - IsStartupEnabled() returns false if value is absent
    - Path value is always quoted to handle paths with spaces (Pitfall 7 from RESEARCH.md)
    - No elevation required — HKCU is always writable by the current user
  </behavior>
  <implementation>
    Static class, three methods. Use Microsoft.Win32.Registry (built-in, no package needed).
    GetCurrentProcess().MainModule!.FileName gives the running exe path.

    SetStartup(true):
      using var key = Registry.CurrentUser.OpenSubKey(RunKey, writable: true);
      string path = Process.GetCurrentProcess().MainModule!.FileName;
      key?.SetValue(AppName, $"\"{path}\"", RegistryValueKind.String);

    SetStartup(false):
      using var key = Registry.CurrentUser.OpenSubKey(RunKey, writable: true);
      key?.DeleteValue(AppName, throwOnMissingValue: false);

    IsStartupEnabled():
      using var key = Registry.CurrentUser.OpenSubKey(RunKey);
      return key?.GetValue(AppName) != null;

    Note for tests: StartupManagerTests.Dispose() cleans up the registry key after each test.
    The test exe path will be written (not BatterMouse.exe) — that is fine for unit testing.
  </implementation>
</feature>

<feature>

  <files>BatterMouse/AppContext.cs</files>
  <behavior>
    - AppContext() constructor creates NotifyIcon with Visible=true and a ContextMenuStrip
    - ContextMenuStrip has a single "Exit" item that calls ExitThread()
    - AppContext() creates HidReader, subscribes to BatteryLevelReceived, starts the reader
    - AppContext() creates BatteryMonitor with ToastHelper.ShowLowBattery as the callback
    - ExitThreadCore() sets _trayIcon.Visible = false before calling base
    - Dispose(bool) disposes the IContainer (which owns NotifyIcon and ContextMenuStrip)
    - No Form is constructed or shown anywhere
    - StartupManager.SetStartup(true) is called in the constructor to ensure auto-start is
      registered whenever the app runs (idempotent: re-writing same value is harmless)
  </behavior>
  <implementation>
    Use the ApplicationContext pattern from RESEARCH.md Pattern 1 verbatim.

    ```csharp
    internal sealed class AppContext : ApplicationContext
    {
        private readonly IContainer _components = new Container();
        private readonly NotifyIcon _trayIcon;
        private readonly HidReader _hidReader;
        private readonly BatteryMonitor _batteryMonitor;

        public AppContext()
        {
            // Register auto-start (idempotent)
            StartupManager.SetStartup(true);

            // Battery monitor wired to real toast
            _batteryMonitor = new BatteryMonitor(ToastHelper.ShowLowBattery);

            // HID reader wired to battery monitor
            _hidReader = new HidReader();
            _hidReader.BatteryLevelReceived += _batteryMonitor.OnBatteryLevel;
            _hidReader.Start();

            // Tray icon
            _trayIcon = new NotifyIcon(_components)
            {
                // TODO Phase 3: replace with a real branded icon
                Icon = SystemIcons.Application,
                Text = "BatterMouse",
                Visible = true,
                ContextMenuStrip = BuildMenu()
            };
        }

        private ContextMenuStrip BuildMenu()
        {
            var menu = new ContextMenuStrip(_components);
            menu.Items.Add("Exit", null, (_, _) => ExitThread());
            return menu;
        }

        protected override void ExitThreadCore()
        {
            _hidReader.Stop();
            _trayIcon.Visible = false;   // prevents ghost tray icon (Pitfall 3)
            ToastHelper.Cleanup();       // ToastNotificationManagerCompat.Uninstall()
            base.ExitThreadCore();
        }

        protected override void Dispose(bool disposing)
        {
            if (disposing) _components.Dispose();
            base.Dispose(disposing);
        }
    }
    ```

    Note: Using SystemIcons.Application as a placeholder avoids a file dependency on
    tray.ico for compilation. Plan 02-01 creates tray.ico; plan 02-04 can switch to
    `new Icon("Resources/tray.ico")` once the file is confirmed valid.

    If SystemIcons is unavailable (not a WinForms context), use the csproj ApplicationIcon
    path approach: `Icon = new Icon(Path.Combine(AppContext.BaseDirectory, "Resources", "tray.ico"))`.
    Add null-check and fall back to SystemIcons.Application if file is missing.
  </implementation>
</feature>
